# 局域网集群同步 · 需求与验收清单

> 状态：已完成（本机双数据目录回环验收；真实第二台机器需在用户局域网复测）。
> 完成项已勾选，实现与最初设想的差异在对应项后注明。
>
> 最后更新：2026-11-01

## 0. 已确认的产品决策

- [x] 一个源客户端创建集群，设置密码；目标客户端输入 IP / 端口 / 密码加入，自动成为下属成员。
- [x] 一个客户端代表一台机器，拥有独立的模型库；A/B 等多个实例共用该客户端的模型库。
- [x] 源端和目标端使用同一个启动器；目标端可以联网。
- [x] **不做永久绑定**。源端每次只选择「源实例 → 一个或多个目标客户机」，不指定目标实例；目标机收到请求后自己选择本机实例（A/B）并确认。多个目标共享同一代次，分别选择、分别确认、分别应用。
- [x] 目标实例只保存历史 `lastApplied`（来源实例、代次、时间、快照），不作为绑定。
- [x] 同步由源端发起；目标端 Agent 通过心跳/拉任务执行。
- [x] A/B 是独立副本，各自保存上次同步状态；目标机在确认时只选一个实例，启动器不会自动替用户把同一台机器的 A/B 同时覆盖。
- [x] 模型默认只新增/修改，不删除；删除必须由用户明确勾选。
- [x] 节点默认不删除目标多余项；删除必须由用户明确勾选。
- [x] ComfyUI 主体版本从第一版就同步，精确到 commit。
- [x] 自定义 wheel 必须原文件打包，不能只依赖 `pip freeze`。
- [x] 本地修改/私有/手工节点必须打包工作区，不要求推到云端 Git。
- [x] 目标在线时普通依赖在线安装；自定义 wheel 用本地文件精确安装。
- [x] 源端展示「自上次成功同步以来」的主体 / 启动参数 / Python / 节点 / 模型五组变化；**不再预览目标机差异**。目标机确认时由 Leader 按目标所选实例计算五组应用清单，并显示同一份日志。
- [x] 启动参数页的监听地址、端口、CORS 头和普通自定义参数随实例同步，并写入目标实例登记；目录类参数（`--models-directory` / `--input-directory` / `--output-directory` / `--base-directory` / `--extra-model-paths-config` 等）保留目标本机值，源端这类参数只展示不写入；目标配置变化也计入漂移指纹。
- [x] 目标实例同步前自动拍快照，失败可回滚；成功后拍同步后快照。
- [x] 目标端有本地改动不再单独弹「目标漂移」拦截：目标机选择实例并确认，即视为同意按源端完整状态覆盖；确认前仍会提示该实例运行状态与上次同步来源，应用前自动拍快照。
- [x] 如果源/目标模型库是同一个 NAS 目录，识别后跳过模型传输。

## 1. 集群与成员

- [x] 源端可创建集群：集群名、密码、监听端口（默认 47821）。
- [x] 集群密码不以明文落盘（PBKDF2-HMAC-SHA256，210,000 次迭代 + 随机 salt；实现时未引入 Argon2id 依赖）。
- [x] 目标端输入 IP / 端口 / 密码加入。
- [x] 加入采用挑战应答，密码不明文传输。
- [x] 加入成功返回 member token；目标端持久化，重启自动重连。
- [x] 目标端上报机器名、平台、启动器版本、实例清单、模型库路径、磁盘余量。
- [x] 源端成员页显示在线/离线、最后心跳、实例、模型库。
- [x] 源端可移除成员；成员可主动退出集群。
- [x] 目标端 Agent 在启动器运行（含托盘）时工作；关闭后任务保留，重连后继续。
- [x] 集群 HTTP 服务只绑定明确端口，默认只读数据 + 固定控制接口。
- [x] 端口被占用时给出清晰错误，不静默换端口。
- [x] 加入失败（密码错、版本不一致、端口不通）有明确提示。

## 2. 同步任务与变更展示

- [x] 源端只选择源实例 + 一台或多台目标客户机；不选择目标实例，也不做目标机差异预览。
- [x] 每次请求生成一个同步代次（generation）；同一代次覆盖全部被选客户机，每台客户机各自一个任务。
- [x] 源端展示「自上次成功同步以来」的五组变化：ComfyUI 主体、启动参数、Python / wheel、节点、模型。
- [x] 上次同步基线按源实例保存在集群配置中；没有基线时按全量展示，并明确提示「尚无成功基线」。
- [x] 目标客户机收到请求后自己选择本机实例；确认时 Leader 才计算「源端 → 所选目标实例」的五组应用清单。
- [x] 目标机选择实例并确认前，不会停止实例、不会写文件、不会拍正式快照；拒绝后源端任务直接取消。
- [x] 确认时若目标实例缺少自定义 wheel 或磁盘不足，明确拒绝并在目标端显示原因。
- [x] 目标端有本地改动时不再拦截：用户在选择实例并确认时即视为同意覆盖，应用前自动拍同步前快照。
- [x] 用户可勾选是否删除目标多余节点。
- [x] 用户可勾选是否删除目标多余模型。
- [x] 任务记录状态：awaiting_confirmation / pending / running / success / failed / cancelled。
- [x] 任务记录开始时间、结束时间、耗时；未领取前显示请求时间，领取后显示实际开始时间。
- [x] 失败报告具体步骤、文件、命令/错误原文。
- [x] 同一客户机同时只允许一个未结束的同步任务；同一目标实例在领取后不会并发执行第二个任务。
- [x] 目标端仍保留「和源端实例比较」只读自检：选择 Leader 源实例与本机实例，重新计算五组差异；不创建任务、不写目标文件。

## 5. 自定义节点

- [x] 干净 git 节点：打包工作区（含 `.git`）并按工作区哈希校验；不强制目标端重新 clone，避免私有/本地提交节点丢历史。
- [x] 有本地修改的节点：打包工作区，目标解压，不 clone 覆盖。
- [x] 有本地提交但未推送的节点：打包工作区，默认包含 `.git`。
- [x] 私有仓库/远端不可达节点：打包工作区，不要求目标访问 Git。
- [x] 手工节点：打包整个目录。
- [x] 保留 `.disabled` 启用态。
- [x] 目标端解压做路径安全检查，禁止目录穿越。
- [x] 目标多余节点删除需用户勾选。
- [x] 目标同名节点内容不同时替换，替换前有同步前快照。
- [x] 节点依赖只来自精确 Python 环境，不自动执行 `install.py`。
- [x] 节点内容变化在预览中列出原因（本地修改 / 私有 / 手工 / commit 变化）。

**最终实测补充（2026-10-31）**
- `cargo test --lib`：164 passed / 0 failed / 5 ignored。
- 本机回环：无 git 的 ComfyUI 核心整包同步、手工节点内容同步、目标多余节点/模型删除并备份、修改模型被覆盖前备份、目标漂移服务端强制确认、自建纯 Python wheel 实际安装到目标 B/C 的 venv 并可 `import`。
- 修复旧 venv 备份跨盘问题：仅在 Python 版本变化/venv 缺失时把旧 venv 同盘临时改名；新环境成功后按设置保留（默认 7 天，可设 0–30 天），到期在下一次同步时清理，失败自动恢复。节点/模型备份增加“复制成功再删源”的跨盘回退；跨盘目录移动有单测。
- 设置页新增「局域网同步」默认值：默认删除多余节点/模型、旧 venv 保留天数；清理开关现在由目标机在确认卡里决定，源端不再代选。目标本地改动由目标机在选择实例并确认时覆盖，不再逐次弹源端漂移确认。
- 修复导入实例的 torch CUDA 轮子解析：源端没有 `engine_detail` 时，从 `torch==x.y.z+cuXXX` 推导 PyTorch 官方索引，并在 PyPI 镜像 + PyTorch 索引并用时加 `--index-strategy unsafe-best-match`，避免只在镜像里找 `+cuXXX` 版本。
- 修复 Leader 未启动时目标端卡顿：Follower 的在线状态和任务列表改由后台 Agent 缓存，`cluster_status` 只读缓存并放到阻塞线程，不再在 UI 命令里同步请求 Leader（Leader 不可达时单次状态查询 < 5 ms）。
- 修复无扩展名自定义包安装失败（如 `env/wheels/cstr`）：源端生成代次时按内容还原 `.whl` / `.zip` / `.tar.gz` 等名字；目标端对旧代次再做一次兼容还原，wheel 从包内 `.dist-info` 重新生成合法文件名。
- 修复 Git / 本地目录安装的自定义包被当成远程文件下载：读取 PEP 610 `vcs_info` 后按固定 commit 在目标端执行 `uv pip install git+URL@commit`；读取 `dir_info` 后把本地源码目录打包成项目制品，目标端解压后安装。`cstr`、`ffmpy.git`、`img2texture.git` 这类包不再走文件扩展名识别。
- `tsc --noEmit` 与 `pnpm build:web` 通过；release 窗口使用内置资源（`http://tauri.localhost/`），不走 dev server。

## 10. 当前实现（2026-11-01：客户机自选实例）

- **同步请求只到客户机**：`sync_request(source_instance_id, target_member_ids)` 只接受目标客户机 ID，最多 16 台、去重、必须在线且至少上报一个实例；每台客户机生成独立任务，目标实例字段为空，状态 `awaiting_confirmation`。源端不再调用目标 diff 预览，也不再选择目标 A/B。
- **目标机自己选实例**：目标端确认卡读取本机实例列表，用户选定 A/B 后调用 `cluster_confirm_job(job_id, target_instance_id, options)`；成员接口 `/confirm` 校验实例属于该成员，才计算「源端 → 所选实例」的五组 diff、拍快照并转 `pending`。确认前不写文件；目标本地漂移不再拦截，`allow_dirty_target` 在服务端置为 true。是否删除本机多出的节点/模型由目标机在这个确认动作里选择，源端不再代选。
- **底栏是唯一发送入口**：源端页面移除「发起同步」卡片；48px 底栏内放源实例下拉、已选客户机摘要和发送按钮，复用统一 `Select` 组件，任务 dock 仍固定在其上方。
- **wheel 不再误报**：`direct_url.json` 的 `archive_info` 哈希会在原始文件被清理后继续保留；wheel 名称按 PEP 503 规范化（`-` / `_` / `.` 等价），比较优先用内容哈希，其次用 VCS 固定提交和文件名，来源路径变化不再单独立案。缺少一侧哈希时保守判为未变，避免「没动过却显示 wheel 变化」。
