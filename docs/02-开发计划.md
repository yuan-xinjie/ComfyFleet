## 1. 产品定位

**一句话**：多实例 ComfyUI 运维面板 —— 建得起来、跑得稳、坏得明白、退得回去。

| 角色 | 诉求 | 对应功能 |
|---|---|---|
| 多环境玩家 | 稳定版与尝鲜版互不污染 | 多实例 + 独立 venv + 独立节点集 |
| 插件重度用户 | 装几十个节点，不知谁搞坏了环境 | **检测 + 冲突解释 + 一键回滚** |
| 教程/工作室 | 复现某版本组合 | 版本升降级 + 快照 |
| 新手 | 点一下就能跑 | 引导式创建 + 控制台 + 错误翻译 |

**v1 非目标**：模型下载站、工作流市场、云端托管、多用户、macOS/Linux、ComfyUI 前端二次开发。

## 2. 架构

```
┌──────────────────────── WebView2 / React 19 ────────────────────────┐
│ 实例 │ 环境体检 │ 节点 │ 版本 │ 设置 │ 控制台 │ 诊断                │
└──────────────────────────▲──────────────────────────────────────┘
                           │ invoke / Channel<T>（serde 强类型）
┌──────────────────────────┴──────────────────────────────────────┐
│ Rust（Tauri Core）                                                │
│  commands/{app,settings,instance,env,pty,diag,node,version}       │
│  services/{pty,process,uv,git,health,depreport}                   │
│  config.rs（GlobalSettings / InstanceConfig，原子写）              │
│  engine.rs（engine-matrix.json 加载与校验）                        │
└───┬──────────────┬───────────────┬──────────────┬────────────────┘
    │ Command      │ portable-pty  │ Command      │ Command
  uv.exe       python main.py     git.exe      cm-cli.py / _probe.py
```

**原则**
1. 所有副作用在 Rust；前端只发意图、只渲染。
2. 长任务统一 `TaskEvent`（`taskId/stage/percent/message/level`），通过 `Channel<T>` 流式回传，可取消。
3. 检测层只读（不改环境），修复才写。
4. 前后端类型单一来源：Rust `serde` 结构 → 生成 TS（`tauri-specta`），CI 校验漂移。

### 2.1 Rust 模块树

```
src-tauri/src/
├─ main.rs                 # windows_subsystem = "windows"
├─ lib.rs                  # Builder / plugins / invoke_handler
├─ error.rs                # AppError { code, message } → Serialize
├─ state.rs                # AppState { settings: RwLock<..>, ptys: Mutex<..> }
├─ config.rs               # GlobalSettings / InstanceConfig / 原子读写
├─ engine.rs               # 引擎矩阵（M1）
├─ commands/
│  ├─ app.rs               # app_info / open_path / open_external
│  ├─ settings.rs          # settings_get / settings_save / mirror_test
│  ├─ instance.rs          # list / create / update / delete
│  ├─ pty.rs               # pty_spawn / write / resize / kill
│  ├─ env.rs               # env_create / env_probe（M1/M5）
│  └─ diag.rs              # diag_run / preview_fix / apply_fix（M5）
└─ services/
   ├─ pty.rs               # portable-pty 会话管理
   ├─ process.rs           # Command 封装：CREATE_NO_WINDOW + Job Object
   ├─ uv.rs                # uv 调用与输出解析（M1）
   ├─ git.rs               # clone/checkout/describe（M6/M7）
   └─ health.rs            # /queue 轮询（M2）
```

## 3. 磁盘布局

```
%APPDATA%\ComfyFleet\
├─ config.json                 # 全局设置（原子写 + .bak + migration）
├─ launcher.log                # 启动器日志（轮转 5×10 MB）
├─ instances\<id>\
│  ├─ instance.json            # 唯一真相源
│  ├─ ComfyUI\                 # git clone（含 custom_nodes\）
│  │  ├─ user\ input\ output\ temp\   # ComfyUI 自己创建和使用
│  ├─ .venv\                   # uv 创建
│  ├─ logs\comfyui-<ts>.log
│  └─ .comfyfleet\
│     ├─ .instance            # 实例归属标记
│     └─ snapshots\           # 快照跟随实例（freeze + 节点 commit + 引擎）
```

## 5. IPC 契约

命令名 `域_动作`；返回 `Result<T, AppError{code,message}>`；长任务返回 `taskId`，进度走 `Channel<TaskEvent>`。

| 域 | 命令 | 里程碑 |
|---|---|---|
| app | `app_info` `open_path` `open_external` | M0 |
| settings | `settings_get` `settings_save` `settings_test_mirror` | M0 |
| instance | `instance_list` `instance_create` `instance_update` `instance_delete` `instance_import` | M0 / M7(import) |
| pty | `pty_spawn` `pty_spawn_instance` `pty_write` `pty_resize` `pty_kill` | M0 |
| env | `env_create` `env_probe` `env_repair` `env_reset` | M1 / M5 |
| engine | `engine_matrix` `engine_apply` | M1 |
| run | `run_start` `run_stop` `run_restart` `run_status` | M2 |
| comfy | `comfy_versions` `comfy_switch` `comfy_rollback` | M6 |
| node | `node_list` `node_install` `node_install_url` `node_update` `node_switch_ref` `node_uninstall` `node_disable` `node_check_deps` `node_market_search` | M7 |
| diag | `diag_run` `diag_last` `diag_export` `diag_preview_fix` `diag_apply_fix` | M5 |

**Channel 约定**
- `Channel<TaskEvent>`：创建/安装/体检/切版本等长任务，**每个任务一个 channel**，前端按 `taskId` 归档。
- `Channel<PtyEvent>`：`{ type: "data", b64 }` / `{ type: "exit", code }`；前端 `TextDecoder({stream:true})` 解码，避免中文截断。
- 全局状态变更用 `app.emit("instance://state")`（低频、可丢）。

**安全基线**：Tauri 2 capabilities 白名单；CSP 收紧（M8 前完成，M0 暂 `null` 并留 TODO）；所有路径参数 `canonicalize` 后校验在允许根内；`open_external` 只允许 `http(s)`。

## 7. 关键流程

### 7.1 创建实例

```
校验(名称/路径/磁盘/端口/引擎)
 → 建目录 + instance.json(state=installing)
 → git clone --filter=blob:none ComfyUI → checkout <tag 或 master>
 → uv venv --python 3.12 --python-preference only-managed
 → 按引擎档装 torch 三元组 → 校验
 → uv pip install -r ComfyUI/requirements.txt（--index-strategy unsafe-best-match）
 → 生成 extra_model_paths.yaml
 → L0+L1+L4 快速体检 → state=ready
失败分类（网络/磁盘/版本/权限）→ 三出口：继续 / 清理重来 / 换引擎
```

### 7.2 启动 / 停止

```
检查 state / 端口（占用则自增）/ 显存（同组 running 则提示）
 → 组装 coreLaunchArgs + server + env（含 PYTHONUTF8=1）
 → portable-pty spawn python main.py --listen … --port … --log-stdout
 → 轮询 GET /queue（1 s，上限 30 min）→ running（记录真实端口）
停止：ConPTY 送 Ctrl+C → 等 8 s → Job Object 全树终止 → stopped（记录退出码与末 50 行 stderr）
```

### 7.3 节点更新（带复检与回滚）

```
snapshot(freeze + 全节点 commit)
 → git fetch + checkout <target>
 → 收集新 requirements → L2 静态
 → L3 预演（合并约束 dry-run）→ 展示 diff
 → 用户确认 → 安装 → L4 冒烟 → L1 复检
 → 失败：checkout 回原 commit + 按 freeze 恢复 → 报告"已回滚"
```

### 7.4 导入已有安装（M7）

```
选目录 → 探测形态：
  A) 含 .venv/ 或 venv/            → 用其解释器
  B) 含 python_embeded/            → 便携版（Windows）
  C) 系统 python 可导入 torch       → 用该解释器（只读校验）
  D) 仅 ComfyUI 源码               → 提示"无环境"，可选新建环境
 → 读 custom_nodes / extra_model_paths / 版本（git 或 requirements 特征）
 → 只登记（imported=true），不复制模型、不改文件
 → 立即体检 → 报告"可运行 / 缺依赖 / 冲突"
```

### 7.5 版本切换

```
git fetch --tags → stable tag 列表 + dev
 → 检出 → 读新 requirements → 增量安装
 → 检查前端包版本 / DB schema / Manager 兼容
 → L1+L4 → 成功；失败自动回滚 commit + freeze
```

### 7.6 进入实例环境终端（手动操作）

```
选实例（cmd 单一形态）
 → 校验 id 为 hex（防路径穿越）→ 读 instance.json
 → 定位 venv：<root>/.venv | venv | ComfyUI/.venv，要求 Scripts\python.exe 存在
 → 组装 env：VIRTUAL_ENV、PATH 前置 Scripts、PYTHONUTF8/IOENCODING、
              PIP_INDEX_URL/UV_INDEX_URL（镜像）、HF_ENDPOINT、实例级 env 覆盖
 → portable-pty spawn（cwd = ComfyUI 目录）+ 打印横幅（实例名/venv/风险提示）
 → 审计日志：谁在何时打开了哪个实例的终端
```

**设计要点**
- **不做"activate 脚本"**：直接注入环境变量比 `activate.bat` 可靠（不依赖 PowerShell 执行策略、不污染 profile）。
- **镜像同步**：手动 pip 也用启动器配置的镜像，避免"启动器能装、手动装不上"的割裂感。
- **漂移检测**：手动改动会打破快照一致性。M3 起在进入前提示"建议快照"，M5 的检测报告要能区分
  "节点声明的依赖缺失" 与 "会话外手动安装导致的版本变化"（依据：freeze 与上次快照的 diff）。
- **安全**：Python REPL 直接执行实例 venv 的 `python.exe`；不开放任意程序（`pty_spawn` 有白名单）。
- **不做**：环境终端里执行 `git` 等操作的封装——那就是普通 shell，用户自己操作即可。

### 7.7 实例设置（实例级 vs 全局的边界）

**归属划分**

| 归属 | 内容 | 理由 |
|---|---|---|
| 全局 | 镜像默认值（PyPI/Git/HF/GitHub 代理）、Python/Git 路径、安装安全策略、UI | 机器级事实，所有实例共享 |
| 实例 | 引擎 + Python、通道、环境变量、镜像覆盖 + HF 离线（「设置」页签）；服务与网络 + 启动参数（「启动参数」页签） | 每个实例跑的东西不一样，端口更是必须独立；启动参数是命令行级别的东西，和表单字段放一起会把设置页撑成两屏 |

**保存时的硬规则**（`apply_update`，纯逻辑可单测）

1. 引擎必须在引擎矩阵里，且该引擎支持所选 Python（cp 标签实测结果）。
2. 改引擎或 Python → 必须有 `allow_env_change`，否则返回 `ENV_CHANGE_NEEDS_CONFIRM`，界面转二次确认；
   确认后状态回 `Uninitialized`，必须重装环境。
3. **改 Python 版本必须把旧 `.venv` 挪走**（重命名成 `.venv.bak-<时间戳>`）。否则 `Scripts\python.exe`
   还是旧解释器，后续装包会装进错版本的 venv —— 这是最难排查的一类问题。
4. 通道切换同步引用：`stable → dev` 置 `master`，`dev → stable` 置空（下次安装时解析最新 tag）。
   否则会出现「dev 通道 + 稳定版 tag」这种自相矛盾的记录。
6. 监听地址必须是合法 IP；`0.0.0.0` 合法但界面必须显式警告（同网段任何人都能访问）。
7. 环境变量名不能含 `=` 或空白；空值行忽略。
8. 镜像覆盖的空串一律归一为 `None` = 继承全局。

**生效时机（界面必须标注，不能让人以为改了立刻变）**

| 字段 | 生效时机 |
|---|---|
| 环境变量 / 镜像覆盖 / HF 离线 | **立即**：进入环境终端时已注入（`pty_spawn_instance` 按「实例覆盖 > 全局」取值） |
| 监听地址 / 端口 / CORS / 启动参数 | 在「启动参数」页保存，**下次启动生效**（`launch_args` 每次启动重新拼 argv） |
| 引擎 / Python | 下一次「安装环境」时生效 |
| 通道（稳定版 / 开发版） | 只能在「版本」页 →「可用版本」面板切（面板内分段开关切换列表，点一行即切）：立即 checkout 并重装依赖，过程在日志弹窗里看；实例设置里不再展示通道与当前版本 |

**首次试用手记（2026-10-28，两个真问题，已修）**

| 问题 | 现象 | 根因 | 修法 | 沉淀为规范 |
|---|---|---|---|---|
| P1 | 进环境后敲 `pip install numpy` 报 `SyntaxError` | 点的是「Python REPL」，进的是**解释器**，`pip` 不是 Python 语法 | 按钮改为「进入环境（Shell）」/「Python REPL」+ tooltip；进入后打横幅说明形态；REPL 内用 `PYTHONSTARTUP` 打印说明并把提示符改成 `yh-py>>>`；REPL 会话顶部常驻「切换到 Shell」 | **任何"终端"入口，必须让用户一眼知道自己在 shell 还是解释器** |
| P2 | 即使进 Shell，`pip install` 也会失败 | `uv venv` **默认不装 pip**（官方行为，非 bug） | `uv venv --seed` + `ensure_pip()` 用 `python -m ensurepip --upgrade` 兜底；已存在的 venv 只补 pip、不重建 | **凡创建 venv 必须校验 `python -m pip --version`**；L0 体检也要加这一项；M1 安装管道同样带 `--seed` |

> P2 是本次最有价值的发现：它会让"环境终端"在最关键的时刻失效，而错误（`No module named pip`）出现在用户已经信任启动器之后。

**P3（2026-10-28 第二次试用）：Shell 里一个键都打不进去**

| 项 | 内容 |
|---|---|
| 现象 | Python REPL 能正常输入，但「进入环境（Shell）」后 PowerShell / CMD 无提示符、无回显，敲键盘毫无反应 |
| 定位手段 | `cargo run --example pty_probe`（仓库内置探针，绕过前端与 Tauri 直接测 PTY）：<br>A) python → **PASS**（写入通道正常）<br>B) cmd 不应答 CPR → **BLOCKED**（只收到 4 字节）<br>C) cmd 应答 CPR → **PASS**（提示符出现、命令执行） |
| 根因 | **ConPTY 启动时先发 `ESC[6n`（光标位置查询），子进程必须等到终端回 `ESC[行;列R` 才继续**。xterm.js 会回（`deviceStatus` 处理器），但回复是由 `onData` 触发的，发生在 `await ptySpawnInstance(...)` 期间，那时 `sessionRef.current` 还是 `null` → 回复被当成"无会话"丢弃 → shell 永久等待 |
| 修法 | 会话 id 未就绪时把 `onData` 的字节**先缓冲**，拿到 id 后立刻补发；连接成功即 `term.focus()`；点击终端任意处强制聚焦；未聚焦时顶栏显示「键盘未聚焦 · 点一下终端」；写入失败不再静默 |
| 沉淀为规范 | **PTY 会话的"输入"必须支持会话就绪前缓冲**——任何"先 spawn 再拿 id"的实现都会丢首帧输入（CPR 只是最典型的一例）。**诊断 PTY 问题先跑探针，别猜前端** |

> **P1 的最终处置（2026-10-28）**：直接把手动终端**收敛为只有 cmd 一种形态**，从根上消除"我在 shell 还是解释器"的歧义。PowerShell 与 Python REPL 入口已移除，`pty_spawn` 的白名单也只剩 `cmd.exe`。P1 的教训仍然有效：**入口越少，越不需要解释**。

**两个实现细节（不处理就会出问题）**

1. **必须 `taskkill /T /F` 杀进程树**：ComfyUI 会拉起子进程，只 `child.kill()` 会留下孤儿进程占着端口，下次启动直接报端口占用。
2. **必须剥 ANSI 颜色码**：ComfyUI 用 colorama 输出 `\x1b[32m[INFO]\x1b[0m`，不剥掉界面上就是一屏 `[32m`。已加回归测试 `strips_ansi_color_codes`。

3. **健康检查不能用"端口通了"当就绪**：`GET /system_stats` 实测返回 200（`real_launch_smoke` 里断言），比只探测 TCP 更接近"服务真能干活"。但要有降级路径——老版本或反向代理下探针可能不通，20 s 后按就绪处理并记警告，而不是一直卡在 `starting`。

**孤儿清理的三条硬约束（2026-10-28 实测）**

1. **必须先校验 pid 身份，再 kill**。pid 会被系统复用，过期 pid 可能指向完全无关的程序。
   校验方式：`Get-CimInstance Win32_Process` 取 `ExecutablePath` + `CommandLine`，要求
   **可执行路径落在该实例的 `venv\Scripts` 下** 且 **命令行含 `main.py`**。
   实测用例：同一个 venv 的 python 跑 `sleepy.py`（不是 `main.py`）→ 拒绝杀，只清记录。
2. **记录解析失败不能当成"没记录"**。踩过一次：用 PowerShell 写的 `run.json` 带 UTF-8 BOM，
   serde 直接解析失败，而旧代码把"解析失败"和"文件不存在"都返回 `None`，于是孤儿永远清不掉、
   日志里一条线索都没有。现在两件事分开处理：剥 BOM 再解析，解析失败要 `warn` 并删掉坏记录。
3. **状态兜底**：没有运行记录但 `state` 停在 `running/starting` 的实例，启动时纠正为 `stopped`
   （上次可能是被强杀，状态没来得及写回）。

**实测揪出的 bug（已修 + 回归测试）**：`pump` 把输出按 `\r`/`\n` 切分时，遇到 `\r\n` 相邻会算出 `start > end` 的区间直接 panic。读取线程死掉 → 输出静默截断 → 校验只拿到 `PY=` 一行就报 `VERIFY_FAILED`。Windows 上 git 的输出全是 `\r\n`，所以这是必现问题。修复后补了 3 个回归测试（`\r\n` 相邻、分块到达、进度节流后终态仍送达）。

**实测揪出的 bug 2：驱动表头格式变了（拦住了安装）**

原实现写死找 `CUDA Version:`。但驱动 610.88 的 `nvidia-smi` 表头是：

```
| NVIDIA-SMI 610.88    KMD Version: 610.88    CUDA UMD Version: 13.3 |
```

解析不到 → `cuda_version = None` → 所有 CUDA 档被判"当前机器不可用" → 点安装直接报 `ENGINE_UNAVAILABLE`。
两个教训：

1. **测试样本是手写的**（`CUDA Version: 13.0`），所以测试一直"通过"，掩盖了真实格式差异。现在样本一律用真机抓到的输出，并加了 `plan_is_consistent_with_machine` 断言"有显卡就必须解析出 CUDA 版本"。
2. **检测不该有拦截权**。已按用户要求改为：`driverOk=false` 只产生 ⚠ 提示（含驱动报告版本 vs 所需版本），安装照常进行；装完的校验步骤会如实报 `CUDA=False`。源码扫描测试 `driver_mismatch_never_blocks_install` 锁住这条，防止以后又"好心拦住"。

**验收**：NVIDIA / CPU 两档各创建一次并 `ready`；`torch.cuda.is_available()` 与引擎档声明一致；venv 内 `pip --version` 可用（`--seed` 校验）；断网时给可读错误。

### 10.1 局域网集群同步（M13，2026-10-30）

- 需求与逐项验收：`docs/04-局域网集群同步.md`。
- 拓扑：一台源客户端创建密码集群；目标客户端只主动连接源端（不需要开放入站端口）。Leader 用自定义 `TcpListener` HTTP 服务提供加入/心跳/任务/产物下载，Agent 轮询 `member/next`。
- 认证：PBKDF2-HMAC-SHA256（210,000 次迭代，随机 salt）落盘，挑战应答加入，token 只存 SHA-256；密码不落明文、不进 URL。集群协议版本升到 2；新旧客户端需要一起更新。
- 同步范围：ComfyUI 本体 commit/worktree、启动参数（监听 / 端口 / CORS / 普通自定义参数；模型/输入/输出等目录类参数保留目标本机值）、Python venv（uv 重建 + freeze + 自建 wheel）、custom_nodes 工作区、客户端级共享模型库。源端只展示「自上次成功同步以来」的变化，不再预览目标差异；源端底栏只负责选源实例和发送，删除本机多出的节点/模型由目标机在确认卡里显式选择。
- 传输：内容寻址 SHA-256，`.part` 原子改名，Range 断点续传；Windows accept 出的 socket 显式恢复阻塞模式，避免大模型下载在发送缓冲区满时被截断。
- 安全：目标端每次同步前 `pre-sync` 快照、成功后 `post-sync` 快照；核心变更带 `CoreRollback`，模型修改先备份旧文件。取消只在尚未落盘时生效；一旦模型/Python/本体/节点开始应用，目标端会完成本次应用并写 `lastApplied`，避免半同步。
- 多目标：源端只勾选客户机（不选实例），共享一个 generation 和源端快照；每台客户机生成独立 `awaiting_confirmation` 任务，目标机确认时自己选择本机实例，Leader 再按所选实例计算 diff。每台目标仍有独立确认/拒绝/日志/快照/`lastApplied`；`sync_request` 先整体校验客户机在线、去重、最多 16 台，再原子入队。等待中的任务按客户机去重，不会给同一台机器叠多个未确认请求。
- 变更基线：`ClusterConfig.last_syncs[source_instance_id]` 保存上次成功同步的源实例快照；`cluster_source_changes` 只比较「上次成功 → 当前」，没有基线时明确提示全量。目标机差异不再参与源端预览。
- 目标端复核：Leader 后台发布本机源实例快照，`GET /api/v1/member/status` 带回源实例摘要；新增 `POST /api/v1/member/compare`（成员 token 鉴权）接收目标端本机 `InstanceState`，只做 `diff_states` 并返回，不建任务、不写文件。目标端 UI 可选 Leader 源实例 + 本机实例反复比较，用于同步后自检。
