# ComfyFleet · 快照功能设计（调研 + 方案）

> 目标：对齐 ComfyUI Desktop 的 Snapshots——把「这个实例此刻是什么状态」记成一条可回滚的时间线。
> 调研对象：`Comfy-Org/Comfy-Desktop`（Electron 版，开源）+ 官方文档。
>
> **状态：P1–P3 已实现并在真机点过（2026-10-29）**，P4（导入/导出）按用户决定暂不做。
> 落地位置：`src-tauri/src/snapshot.rs`（模型 / 采集 / 存储 / 差异 / 恢复）、
> `src-tauri/src/commands/snapshot.rs`（IPC）、`src/views/Snapshots.tsx`（时间线页签）、`src/styles.css` 的「快照」段。
> 与下文设计的差异只有三处（都是用户拍板的）：多余节点**删**、多余包**卸**、**不做**导入导出。

---

## 1. 官方是怎么做的（已核对源码）

文档：<https://docs.comfy.org/installation/desktop/usage/snapshots>
源码：`src/main/lib/snapshots/{types,store,diff,restore,exportImport,tabData}.ts`、`src/main/lib/nodes.ts`、`src/main/lib/pip.ts`

### 1.1 一条快照记什么

```ts
interface Snapshot {
  version: 1 | 2            // 2 才有 torchStack
  createdAt: string         // ISO
  trigger: 'boot' | 'restart' | 'manual' | 'pre-update' | 'post-update' | 'pre-deps' | 'post-restore'
  label: string | null      // 手动备注，如「加 LCM 之前」
  comfyui: { ref, commit, releaseTag, variant, baseTag?, commitsAhead? }
  customNodes: ScannedNode[]        // 每个节点的身份 + 版本 + 是否启用
  pipPackages: Record<string, string>  // uv pip freeze 的结果
  pythonVersion?: string
  updateChannel?: string
  torchStack?: ...          // v2：torch/torchvision 的「可复现身份」
}
```

`ScannedNode`（`nodes.ts`）的分类规则很关键，决定了「能不能装回来」：

| type | 判定 | 记录字段 | 恢复方式 |
|---|---|---|---|
| `cnr` | 有 `.tracking` 文件（ComfyUI Manager 装的） | `id`=pyproject 的 name、`version` | 按 CNR 版本重装 |
| `git` | 有 `.git/` | `id`=目录名、`commit`、`url` | git clone + checkout |
| `file` | `custom_nodes/` 根下的单个 `.py` | 文件名 | 随核心仓库，不单独恢复 |

扫描两个位置：`custom_nodes/<name>`（启用）与 `custom_nodes/.disabled/<name>`（禁用），
并排除 `.开头的目录`、`__pycache__`、以及核心自带的 `websocket_image_save.py`。
**没有 `.git`、没有 `pyproject.toml`、也没有任何顶层 `.py` 的目录不算节点**（否则误建的模型目录会被记成永远恢复不了的节点）。

### 1.2 存在哪、留多久

- 位置：`<install>/.launcher/snapshots/`，一条一个 JSON，文件名 `YYYYMMDD_HHMMSS_mmm-<trigger>-<rand>.json`；
  先写 `.tmp` 再 `rename`（原子落盘）。
- 排序：按 `createdAt` 字符串倒序（= 时间线，最新在顶）。
- 保留：`AUTO_SNAPSHOT_LIMIT = 200`，只裁 `boot` / `restart` 且**没有 label** 的旧条目；
  `manual` / `pre-update` / `post-update` / `post-restore` 永不自动删。
- 去重：`captureSnapshotIfChanged()` 只在状态真的变了才写（比较 ComfyUI commit、节点集合、包集合、torch 栈身份）。
  另外有两处「整理」：连续两次 `restart` 只保留最终态；`pre-update` 与上一条状态相同就删掉。

### 1.3 什么时候自动拍

官方文档 + 源码：每次启动（boot）、重启（restart）、更新前后（pre/post-update）、恢复后（post-restore），
外加手动。**注意它的产品约束**（`snapshots/AGENTS.md` 写得很明确）：

> 快照历史里只允许出现「这台机器真的经历过的状态」；最新一条必须是当前真实状态。

所以导入别人的快照时，**先 stage 成 restore 目标，恢复成功之后才提交进历史**，失败就什么都不写——
否则会出现「恢复失败但目标快照显示为最新」的错觉（他们 bug #1137 的教训）。

### 1.4 恢复的顺序和护栏

1. **快照目标校验**（import 场景）：`type === 'comfyui-desktop-2-snapshot'`、版本号、trigger 白名单、
   节点 `dirName` 必须是安全的路径片段、包名必须匹配 `^[A-Za-z0-9][A-Za-z0-9._-]*$`（防命令行注入）、版本号格式受限。
2. **ComfyUI 版本**：`git fetch` + `git checkout <commit>`（commit 先按 `^[a-f0-9]{7,40}$` 校验；HEAD 已经匹配就连 git 都不跑）。
3. **自定义节点**：
   - 快照里有、本机没有 → 按 `type` 重装（cnr 按版本，git 则 clone + checkout 到记录的 commit）
   - 两边都有但 commit/版本不同 → 切换；启用状态不同 → 改名进/出 `.disabled`
   - 本机有、快照里没有 → **删除**（`fs.rm`），`ComfyUI-Manager` 自身除外
   - 新装/切换过的节点，恢复后跑它们的 `requirements.txt`（`repairNodeRequirements`）
4. **pip 包**：
   - 先 `uv pip freeze` 抓当前，算出 install / change / remove 三组
   - **保护名单**跳过：`pip/setuptools/wheel/uv` + torch 全家（`torch*`、`nvidia*`、`triton*`、`cuda*`、`rocm*`… 精确名 + 前缀两类规则），
     这些交给它自己的 torch 事务，pip 同步不许碰
   - 改动前对「会被覆盖/删除的包」在 site-packages 里做定向备份，失败/取消就回滚（`RestoreRevertOutcome` 会如实报告回滚做了什么）
   - 单次批量 `uv pip install a==1 b==2 …`，失败再降级为逐个装并汇总失败项
5. **收尾**：写一条 `post-restore` 快照（记录恢复后的**真实**状态，而不是「期望状态」）。

### 1.5 分享/导入

单个 `.json` 信封：`{ type, version, exportedAt, installationName, snapshots: [...] }`。
导入时只用文件里**最新**那一条；能精确复现就入历史，不能就存一条「实际结果」快照。
跨机器还会校验 torch 栈是否可应用（我们这一步不适用，见下）。

## 2. 我们的差异（决定了要砍掉什么）

| 官方 | 我们 | 影响 |
|---|---|---|
| CNR + git 两种节点 | 只有 git clone（`.disabled` 后缀表示禁用） | 快照类型只留 `git` / `manual`；恢复=clone+checkout |
| 有独立 torch 事务与 CUDA 矩阵 | 我们只按 `engine-matrix.json` 选 wheel 装一次 | 不做 torch 栈身份；torch 系一律进保护名单，不参与恢复 |
| 数据在 `.launcher/` | 快照跟随实例 | 存 `<实例根目录>\.comfyfleet\snapshots\`；旧 `data\snapshots\<实例 id>\` 自动迁移，远程/只读目录回退到启动器数据目录 |
| 实例就是整个安装 | 一台机器多个实例，各有 venv + ComfyUI 仓库 | 快照**按实例**隔离，不跨实例合并 |
| 恢复可取消 | 我们已有流式子进程 + 控制台 | 复用 `proc::run_stream` + 进度事件 |

另外两个我们天然更严的点：

- 我们的 ComfyUI 仓库是**启动器自己 clone 的**，`version::switch_to` 已经有 fetch/checkout 逻辑，可直接复用；
- 我们的 venv 固定在 `root\.venv`，`uv` 路径由 `env::resolve_uv()` 统一解析 —— 不用像官方那样做 adopted 安装的兼容。

## 3. 数据模型（Rust）

```rust
#[derive(Serialize, Deserialize, Clone)]
#[serde(rename_all = "camelCase")]
pub struct Snapshot {
    pub version: u32,                 // 1
    pub id: String,                   // 文件名（不含 .json）
    pub created_at: String,           // RFC3339
    pub trigger: SnapshotTrigger,     // manual/boot/restart/pre-update/post-update/pre-deps/post-restore
    #[serde(default)]
    pub label: Option<String>,
    pub comfyui: SnapshotCore,        // channel, ref, commit, version
    pub python: SnapshotPython,       // version, torch
    #[serde(default)]
    pub server: Option<ServerOpts>,   // 启动参数：listen / port / corsOrigin / extraArgs；老快照为 None
    pub nodes: Vec<SnapshotNode>,     // name, url, commit, enabled, has_requirements
    pub packages: BTreeMap<String, String>, // 只存 uv pip freeze 能解析成 name==version 的行
    #[serde(default)]
    pub note: Option<String>,         // 采集时的告警（如 freeze 失败）
}

pub struct SnapshotCore { pub channel: String, pub git_ref: String, pub commit: Option<String>, pub version: Option<String> }
pub struct SnapshotNode { pub name: String, pub url: Option<String>, pub commit: Option<String>, pub enabled: bool }
```

落盘示例：

```json
{
  "version": 1,
  "id": "20261029_215500_123-manual-a1b2c3",
  "createdAt": "2026-10-29T21:55:00.123+08:00",
  "trigger": "manual",
  "label": "加 LCM 之前",
  "comfyui": { "channel": "stable", "gitRef": "v0.43.1", "commit": "3f1c2ab…", "version": "0.43.1" },
  "python": { "version": "3.12.8", "torch": "2.6.0+cu124" },
  "server": { "listen": "127.0.0.1", "port": 8188, "corsOrigin": null, "extraArgs": ["--lowvram"] },
  "nodes": [{ "name": "ComfyUI-Manager", "url": "https://github.com/ltdrdata/ComfyUI-Manager", "commit": "abc1234", "enabled": true }],
  "packages": { "aiohttp": "3.9.5", "torch": "2.6.0+cu124" }
}
```

### 存放与保留

- 目录：`<实例根目录>\.comfyfleet\snapshots\<id>.json`，原子写（复用 `config::atomic_write`）。
  远程实例或本地目录不可写时回退到 `<数据目录>\snapshots\<实例 id>\<id>.json`；
  旧版数据目录会在首次读取时自动迁移。
- 上限：自动类（boot / restart）**最多 200 条**，手动/更新前后/恢复类永不自动删（与官方一致）。
- **最新一条永远等于当前状态**：这是官方用血的教训换来的约束，我们的触发逻辑要照抄（见 §5）。

## 4. 采集（capture）

一次采集 = 三件事，全部只读、几秒内：

| 项 | 命令 | 备注 |
|---|---|---|
| ComfyUI 提交 | `git -C <root>\ComfyUI rev-parse HEAD` + `describe --tags --always` | 复用 `version::read_version` |
| 启动参数 | 直接读实例配置 `inst.server` | 监听 / 端口 / CORS / 自定义参数原样保存；存储路径属于本机配置，不记录 |
| 节点 | `nodes::scan_nodes(<root>\ComfyUI\custom_nodes)` | 已有：name / kind / url / commit / enabled |
| 包 | `uv pip freeze --python <root>\.venv\Scripts\python.exe` | 新写一个 `parse_freeze()`：只收 `name==version`，跳过 `-e`/`@ file://`/`#` 注释 |

失败降级：freeze 失败不影响整条快照，把 `note` 写上「包列表采集失败：…」，避免「一条都拍不了」。
`python.version` 取 `<venv>\Scripts\python.exe -V`（或实例里已记录的 `pythonVersion`）。

## 5. 触发与去重

- **手动**：按钮 + 可选备注。永远写一条。
- **启动**（`boot`）：实例启动成功后拍；与最新一条 `states_match()` 相同就跳过（不然时间线全是重复）。
- **版本切换**（`version_switch` / `version_update`）：切换前拍 `pre-update`，成功后拍 `post-update`；
  若 `pre-update` 与上一条完全相同则删掉它（官方同样处理）。
- **节点安装/更新/删除**：暂不自动拍（操作已有控制台日志）；先上 P3 再说 —— 这类操作最该有快照，但拍得太密会淹没时间线，建议做成「安装前自动拍 + 24h 内去重」。
- **恢复前**：必拍 `pre-restore`（这是「能不能反悔」的关键兜底）。

## 6. 恢复（restore）

### 6.1 预检（不满足就明确拒绝，而不是拍到一半）

1. 实例必须处于**已停止**状态；
2. ComfyUI 核心仓库的 `git status --porcelain` 必须干净（有未提交改动就返回 `DIRTY_TREE` 并列出前几项；这和 `switch_to` 的策略一致）。它检查的是 `<实例>\ComfyUI` 本身，不是 `custom_nodes` 里各节点的独立仓库；如果 `custom_nodes` 没被 `.gitignore` 忽略，也可能出现在这里；
3. 快照可解析 + 版本号认识；
4. 目标 commit 属于该仓库（`git cat-file -e <sha>` 校验，防伪造文件）。

### 6.2 步骤（每步失败都保留已完成的进度，并把失败项列出来）

```
0. 拍 pre-restore 快照（失败则中止——没有退路不允许继续）
1. ComfyUI 版本：git fetch（失败可跳过）→ git checkout <commit> → 校验 HEAD
2. 节点：
   2.1 快照有、本机无 → git clone <url> → checkout <commit>；clone 失败记 failed
   2.2 commit 不同 → fetch + checkout
   2.3 启用状态不同 → 改名 <name> ↔ <name>.disabled（复用 nodes_toggle 的规则）
3. 包：
   3.1 freeze 当前环境
   3.2 跳过保护名单；算出 install / change / remove
   3.3 uv pip install 全部改动项（一次性；失败则逐个重试并汇总）。镜像 `--index-url` 只加给 install；`uv pip uninstall` 不接受该参数，卸载命令不能带镜像
   3.4 （可选开关，UI 默认勾选）移除多余包：批量 `uv pip uninstall`，失败再逐个重试
   3.5 安装后重新 freeze 对账：装包过程新带进来的依赖也按快照卸掉，再 freeze 一次复核；仍多出的包写进 `leftover`，在恢复详情里列名，不静默成功
4. 启动参数：快照有 `server` 就完整覆盖实例的 `listen / port / corsOrigin / extraArgs`（不做合并，保证恢复后的启动行为与快照完全一致）；老快照没有 `server` 就保持当前设置并在报告里注明
5. 不再自动拍 post-restore 快照：恢复前那条 `pre-restore` 就是回滚点；恢复完成后由用户决定是否手动记录。
```

失败与取消：不做半自动回滚（官方那套 site-packages 定向备份 + revert 太重，收益低），
改为**一条命令即可反悔**——「恢复 pre-restore 快照」在 UI 上一键可达；同时在结果面板里列出
`failed` 项和「现在与目标快照的差异」，让用户知道停在哪。

### 6.3 保护名单（绝不参与恢复）

`pip / setuptools / wheel / uv / torch / torchvision / torchaudio / triton / nvidia-* / cuda-* / rocm-*`。
理由：这些包由启动器的引擎矩阵决定（换错就是驱动不兼容 + 几个 GB 重下），
跨机器快照更是如此。恢复时对它们**只报告差异**（「torch 从 2.6.0+cu124 变成 2.5.1+cu121，已跳过」）。

## 7. Diff（详情页与恢复预览共用）

按官方 `diffSnapshots()` 的语义实现，字段对齐：

```
comfyuiChanged / comfyui{from,to}
launchChanged / launch{from,to}          // ServerOpts；任一侧没有 server 时按「未记录」处理
nodesAdded[] / nodesRemoved[] / nodesChanged[]{name, from{commit,enabled}, to{...}}
pipsAdded[] / pipsRemoved[] / pipsChanged[]{name, from, to}
```

两个视角：
- **这条快照改了什么** = `diff(上一条, 这条)`（最老一条没有）
- **恢复它会改什么** = `diff(当前真实状态, 这条)`（最新一条没有，因为没得恢复）

列表折叠态显示：trigger 标签 + 时间 + ComfyUI 版本 + 计数 pill（`+2 节点 · −1 包 · 版本变了 · 启动参数`）。

## 8. 界面

新页签「快照」（第 9 个，快捷键 Ctrl+9），结构：

```
┌ 快照 ─────────────────────────────── [创建快照] [导入] [导出全部] ┐
│ ● 手动 · 加 LCM 之前      10-29 21:55   v0.43.1   +2 节点 · 3 包改动 │  ← 最近
│ ● 启动                    10-29 21:40   v0.43.1                      │
│ ● 版本切换后              10-28 22:10   v0.42.0   −1 节点            │
└───────────────────────────────────────────────────────────────────┘
```

- 点一行展开：完整节点/包清单（包只显示数量 + 可搜索的列表）、两个 diff 折叠块、`[恢复] [导出] [删除]`。
- 恢复：先弹预览（diff + 保护项 + 「会先拍一条 pre-restore」），确认后进入执行视图——
  复用控制台那套流式输出 + 阶段进度，失败项在结束时高亮。
- 最新一条没有「恢复」按钮；删除要二次确认（和现有删除实例一致）。

## 10. 分阶段

| 阶段 | 内容 | 验收 |
|---|---|---|
| P1 | 模型 + 采集 + 存储 + 保留 + 列表/详情 UI + 手动拍/删 | 拍一条 → 关掉重开 launcher 还在；连续拍两条相同状态会去重（boot 场景） |
| P2 | 恢复：版本 + 节点（含启用/禁用）+ 包（装/换），保护名单、恢复前快照、流式输出 | 把节点切到旧 commit 后恢复快照能回去；运行中/脏工作区被拒绝；torch 不被换 |
| P3 | 自动触发（启动、版本切换前后）+ diff 预览 + 一键回滚到 pre-restore | 时间线语义正确：最新一条 == 当前状态 |
| P4 | 导入/导出信封 + 分享 + 跨实例创建 | 导出给另一个实例导入，能复现节点与包 |

## 11. 风险与取舍

- **pip 同步是最危险的一步**：快照里没有的多余包默认卸掉，但 UI 上必须显式保留开关；torch 系一律跳过；
  安装失败只汇总、不猜、不静默。卸载失败或仍有残留时，报告要列名，不能显示成完全成功。
- **磁盘**：一条快照通常 50–200 KB（包列表为主），200 条 ≈ 20 MB，可接受；不做压缩。
- **并发**：同一实例的采集/恢复要串行（官方用 per-install mutex）；我们用 `AppState` 里按实例 id 的锁。
- **和「启动参数 / 存储」的关系**：启动参数（监听 / 端口 / CORS / 自定义参数）现在**随快照记录并恢复**，
  因为换环境后启动行为本身也是「那一刻的状态」；存储路径仍然不记录——模型 / 输入 / 输出目录是目标机的本机配置，
  跨机恢复时不应该把源机路径带进来。同步时的启动参数仍按原来的规则合并，保留目标机目录类参数。

## 12. 实现落地记录（P1–P3）

### 12.1 文件与存储

| 位置 | 内容 |
|---|---|

| `src/views/Snapshots.tsx` | 时间线、展开详情（与上一条的 diff + 节点/包清单）、恢复预览与选项、进度日志、报告与「回滚到恢复前」 |
| `<实例根目录>\.comfyfleet\snapshots\<id>.json` | 一条一文件，`config::atomic_write` 原子写；`<id>` = `YYYYMMDD_HHMMSS_mmm-<trigger>-<rand>`；删除登记但保留文件时快照仍随实例存在，`purge` 时随根目录一起删 |
| `<实例根目录>\.comfyfleet\snapshots\<id>.nodes\` | 节点内容 payload：手工节点 `<name>.zip`；git 脏节点 `<name>.patch` + `<name>.untracked.zip`。删除/裁剪快照时随 JSON 一起删；老快照没有这个目录 |

### 12.2 触发与裁剪

- `boot`：`start_instance` 起进程后**后台线程**拍，`states_match` 与最新一条相同就跳过（不拖慢启动）。
- `pre-update` / `post-update`：`version_switch` / `version_update` 前后各一条；`pre-update` 与上一条完全一致时跳过。
- `pre-restore`：`restore()` 内部强制拍；`post-restore` **不再自动拍**（旧版本留下的 post-restore 快照仍可正常展示/删除）。
- 自动裁剪：只裁「`trigger == boot` 且没有备注」的，保留最新 200 条；手动、更新、恢复类永不自动删。

### 12.3 恢复顺序（实际实现）

1. 预检：实例未运行（命令层）、`git status --porcelain` 为空、目标 commit 在仓库里（`git cat-file -e`，没有就 `fetch origin --tags` 再试）。
2. 拍 `pre-restore`。
3. 版本：`git checkout -q <commit>`，失败依次重试 `fetch origin --tags` → `fetch origin <sha> --depth 1`。
4. 节点：删除快照里没有的（目录名做安全校验，`.` 开头 / 含分隔符的跳过）；缺的按内容模式恢复——`content=full` 从 `<id>.nodes/<name>.zip` 解包，git 节点 `clone` 后 checkout 到快照提交；commit 不同的 `checkout`（先 `reset --hard` + `clean -fd`，避免脏工作区挡住切换）；`content=patch` 在 checkout 后 `git apply --binary` 快照的未提交 diff，再解未跟踪文件 zip；`content=null` 的干净节点清掉工作区多出的改动；启用态不同就 `.disabled` 改名。
5. 包：`uv pip freeze` 取当前 → 与目标求差集 → `uv pip install name==version`（40 个一批，整批失败再逐个重试以定位失败项）→ `uv pip uninstall` 多余包（批量失败再逐个重试）。**镜像 `--index-url` 只加给 install**：`uv pip uninstall` 不接受该参数，之前把镜像拼进卸载命令是「包没被卸载」的根因。装完再 freeze 一次，把安装过程新带进来的依赖按快照卸掉，并再 freeze 复核；仍残留的包写进 `leftover` 并在 UI 列名。保护名单 `torch/torchvision/torchaudio/triton/torio/functorch` + 前缀 `torch-*/triton-*/nvidia-*/cuda-*/rocm-*/pytorch-triton-*` + `pip/setuptools/wheel/uv` 一律跳过，只在报告里列出差异。
6. 启动参数：`target.server` 存在就完整覆盖实例的监听 / 端口 / CORS / 自定义参数，报告里给出 `from → to`；老快照为 `None` 时跳过并提示「老快照未记录，保持当前设置」。
7. 恢复完成后**不自动拍快照**；命令层把 `instance.json` 的 `comfy.commit/ref/version/channel` 和 `server` 对齐到真实结果。

失败不抛给前端「一半成功」的错误：`restore` 返回结构化 `RestoreReport`（core/nodes/packages 各自的成功列表 + `failed[{name,error}]` + `warnings`），失败项在报告里逐条列出，用户可以「回滚到恢复前」。

### 12.4 已知边界

- 没有 venv 的实例（导入的、或环境没装完）：包这一步直接失败并说明原因，版本与节点照常恢复。
- 不含 `.git` 的 ComfyUI 目录：直接拒绝恢复，提示只能管理节点与包。
- 节点 URL 缺失（手工拷进来的）：新快照会把整个节点目录归档（排除 `.git`、`__pycache__`、虚拟环境/`node_modules` 等），恢复时不依赖 URL；老快照没有归档，仍记为失败。
- git 节点有未提交改动：新快照存 `git diff HEAD --binary` 与未跟踪文件；恢复时先清工作区再 checkout 快照 commit，然后叠回 diff。被 `.gitignore` 忽略的文件不会被快照收录。
- 归档失败（磁盘满、文件被占用等）：节点标成 `content=missing` 并写进快照 `note`，恢复时明确报「归档缺失」，不会误当成干净节点去 reset。
- 归档会占用额外磁盘；手工节点目录很大时快照也会很大，删除快照会连同 `.nodes` payload 一起删。
- 本次改动前拍的老快照没有 `server` 字段：恢复时不动启动参数，结果卡明确写「老快照未记录，保持当前设置」。
- `restore_preview` 需要 `uv pip freeze`，慢 IO 时点击「恢复到这一刻」会有 1–2 秒的无反馈期（按钮变「读取差异…」）。
### 12.5 界面（对齐 Desktop 的 Snapshots）

界面不是「一堆卡片」，而是 Desktop 那条**时间线轨道**：

- 轨道：左侧竖线 + 每行一个圆点；`post-update` / `post-restore` 用橙色点，其余灰点；
  第一个节点是「创建快照」（虚线盒，里面是备注输入 + 记录当前状态），恢复中/成功/失败
  都占用这个槽位（Desktop 同样把 restore 的状态卡放在 Save 里，我们多做了一步：
  结果卡里能展开失败项、并给「回滚到恢复前」）。
- 行：第一段 `触发来源 + 最新徽标` / `相对时间 + 箭头`，第二段 `版本胶囊 + 节点胶囊 + 包胶囊 +
  启动参数胶囊`（`+n −n ~n` 三色）；备注存在时版本胶囊显示备注，否则显示 `上一条版本 → 本条版本`。
- 展开：卡片里是 `节点/包计数`、备注、`这条快照改了什么`（与上一条的 diff）、
  `快照里的节点 N · 包 N`（明细）、`恢复它会改动什么`（与当前状态的 diff，展开时才
  现场采一次，对应 Desktop 的 lazy diff）、右下角「恢复到这一刻 / 删除」。
- 差异视图：标题小号大写（`ComfyUI 版本` / `自定义节点 (n)` / `Python 包 (n)`），
  行是等宽字体 `+ / − / ~`，超 12 行折叠成「…还有 n 项」。
- 确认：点「恢复到这一刻」弹**恢复确认窗**（时间 + 目标、会改什么、两个「删多余节点 /
  卸多余包」开关、torch 保护清单、运行中警告），不再把确认卡放到页面顶部；确认后弹窗关闭，
  回到轨道顶部看进度，结束后结果卡仍占「创建快照」槽位。

参考实现（Vue，`Comfy-Org/Comfy-Desktop`）：`src/renderer/src/views/comfyUISettings/SnapshotsView.vue`、
`SnapshotRow.vue`、`src/renderer/src/components/SnapshotDiffView.vue`；我们按本项目的
token 与组件重画，交互与信息层级保持一致。

**顺手修的两个数据问题**：差异里的新增/删除节点现在带 `commit` 与启用态（`NodeRef`），
所以行里能显示 `+ comfyui-impact 5e4d3c2`；节点 commit 只在一侧读不到时不再算「变更」
（否则非 git 安装的节点会让每条快照都显示改动）。
